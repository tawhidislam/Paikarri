# Supplier store profile pictures

Suppliers can upload, replace or remove their store logo/picture at **Dashboard → Your business** after creating the business profile. The independent picture editor preserves unsaved business-profile fields. Pictures appear on the public supplier storefront and homepage/directory supplier cards; initials remain the fallback for absent or unavailable images.

The browser accepts JPEG, PNG and WebP sources up to 20 MB/40 megapixels. It always re-encodes store pictures to WebP, limits the longest side to 512 pixels without upscaling, strips metadata, and enforces a final 256 KiB limit. This is separate from identity/trade/bank documents. The UI shows the original and uploaded sizes. Source images are not uploaded.

Migration `20261019003600_store_profile_pictures.sql` adds a nullable business picture path and private `store-images` bucket. Storage enforces WebP MIME and 256 KiB object size. Paths are unique `owner-id/business-id/random-id.webp` values; supplier ownership is enforced independently of UI controls. No overwrite/update policy is granted. Guarded, optimistic `set_store_picture()` checks the expected old picture and uploaded metadata before attachment. Current pictures cannot be deleted from storage until unlinked. Replacement removes the old object only after the new association succeeds; failed associations remove the new object where possible. Storage/network cleanup failures may leave private unlinked objects for operator cleanup.

Public signing is allowed only for a store's current picture when the business meets the existing public-catalog eligibility rules. Unpublished/suspended businesses cannot issue new public image URLs. Owners can preview/remediate their own pictures; existing administrative visibility remains authorized. Signed URLs last five minutes and refresh after four minutes while mounted. Previously issued URLs retain their existing expiry.

Cloud migration 36 has been applied. SQL authorization tests in `supabase/tests/store_pictures.sql` run in a rolled-back transaction. They cover owner/cross-account writes, stale updates, anonymous access, public eligibility, suspension, cleanup protection and overwrite denial. A real storage smoke test using the designated fictional supplier confirmed upload, owner preview, guest denial and overwrite denial; its temporary unlinked object was removed without changing a business picture.

Browser tests in `tests/e2e/store-picture.spec.ts` exercise actual WebP output, dimensions/size, upload/replacement/removal, public storefront display, unsaved-form preservation, stale association cleanup, unsafe files, upload errors and narrow Bangla layouts. `image-upload.spec.ts` covers the shared compressor's transparency/document behavior. No production frontend deployment is part of this change.

Shared-compressor browser checks also passed. The regression pass caught and fixed a six-category mobile spacing issue so inventory remains visible within the expected first-screen bounds.
